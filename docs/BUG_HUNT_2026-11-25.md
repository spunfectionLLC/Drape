# Bug hunt, 2026-11-25 (overnight review)

Two reviews of the code (round 2 below) for anything that could cause problems, newest code first (multi-garment, Simple mode,
larger avatars), then the server, the website build and exports. Branch `bug-hunt`, four commits; every fix has
a test in `tests/test_v27_bughunt.py`. Nothing here was deployed.

## Fixed

### Security
| Problem | Effect | Fix |
|---|---|---|
| Names from a shared `.drape` / `.garment` file went into the page's HTML (piece, edge, garment names; garment colour and id in attributes) | Opening a crafted file ran its script on spunfection.studio (confirmed: the test's payload ran on the old code) | Every string a file brings is cleaned once on load (`cleanFile`); ids and colours must have their own shape; renamed pieces can't take `< > " \` &` |
| The desktop studio answered any POST, whatever its Content-Type | Any website open in another tab could drive the studio on 127.0.0.1 (start drapes, write exports) | POSTs must be JSON, from the studio's own origin, to an IP or this computer's name |
| The request's `block` name (and a size run's table / paper) became the export's file path | `../../x` wrote a file outside the temp folder; quotes went into the download header | Names are letters, digits, `_`, `-` |

### Things that hung or crashed
| Problem | Fix |
|---|---|
| A desktop drape worker that died (out of memory, killed) left the page on "Sewing the pieces…" for ever | The job ends with an error once the process is gone |
| Website: a failure finishing the drape in Python (e.g. a NaN from the GPU) left "Checking the fit" for ever | The job ends with the error; a failed GPU drape frees the prepared job (`/api/drape_cancel`) |
| Inches typed into every cm field crashed the avatar fit before the "if you measured in inches" message could show; height 0 crashed; a negative waist built for 69 s; text gave a Python error | Clear messages about the number (never about the person) |
| A frozen shape from a file with one stray far point could grow the collision grid to billions of cells | The grid grows at most 40 cm past the body's; a damaged mesh says so |
| Pattern values from a file weren't limited (a 1e6 cm length) | Numbers only, within twice the slider's span past either end |
| A file with units other than cm/in threw on open | Units are cm or in |
| A file naming a pattern or fabric this copy doesn't have broke the Design step / gave a KeyError at drape time | It opens (pick a pattern / jersey) and the toast says what was missing |

### Wrong results
| Problem | Fix |
|---|---|
| Switching garments while Live ran kept simulating the old garment; the next restart carried its cloth over by piece name and cleared the new garment's drape | Switching stops Live; Live refuses a frozen garment |
| Exports, the outfit export and "tap the garment" used the latest job even when that re-drape failed | The job behind the drape on screen (`drapeJob`) |
| The free editor's answer for one garment could land on another after a switch | Dropped unless it's for the active garment |
| Opening a project whose garment has no pattern showed the previous project's pattern panel | The picker |
| Browser storage full (frozen shapes are big): autosave failed silently, a reload brought back an older project | Kept without the frozen shapes, and a one-time message to save a file |
| Renaming a garment: Escape saved anyway | Escape cancels |
| Deleting a garment left the undo position pointing at the wrong step | The position moves back by the steps removed |
| Trousers "Shorts" set the hem 48.5 cm above the floor on a slider that stopped at 40 | Slider to 75 cm |
| Other garments re-draped after a failed drape | Only after one that worked |
| A frozen garment in a file without its frozen shape couldn't be draped or collide | Opens unfrozen |
| Unknown avatar / drape ids (the studio restarted under an open page) showed a bare id | A sentence saying what to do |
| Each export and drape left a temp folder (339 export folders were in %TEMP% on Tyler's PC) | Export folders removed after reading; drape folders at exit |

## Round 1's open items, done (branch `bug-hunt-2`)
| Item | Now |

## Round 2
### Things that hung, or would have
| Problem | Fix |
|---|---|
| A piece typed 10x too big (6 m across) meshed for minutes on every edit; on the website the page froze | Refused before meshing above 100,000 points (the largest design that ships is about 10,000), with a message about the size. A file's `spacing_cm` is kept to 5 mm..5 cm |

## Found, not changed (decisions or low risk)
- **A chest of 1,000,000 cm builds an avatar without a word.** Left alone: no upper limit on any measurement
  (CLAUDE.md, "Bodies").
- **No CSP on the desktop studio's page.** Every browser test waits with Playwright's string predicates, which
  use eval; the desktop page loads nothing from other hosts and files are cleaned on open. Worth it later,
  with the tests moved to `() => ...` predicates.
- **Laser nesting is quadratic.** Packing sheet by sheet from what's left would lift the 10-garment limit.
- **Ctrl+Z in an open dialog** (My fabric, say) undoes the design behind it.
- **The server's error answers include the Python traceback** (local app; the website's are in the page anyway).
